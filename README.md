# Tyaga Pyriatyn — сайт + Telegram-бот

Монорепозиторій (npm workspaces):

```
web/         — сайт на Next.js (App Router, Tailwind v4)
bot/         — Telegram-бот на Telegraf
packages/db/ — спільна база даних (SQLite + Drizzle ORM), яку використовують і сайт, і бот
data/        — файл SQLite-бази (tyaga.db)
```

Сайт і бот працюють з **однією й тією самою базою даних**: бронювання й замовлення, зроблені
через сайт, одразу видно в базі, яку читає бот, і навпаки.

## Що вже працює

- Каталог смаків (92 позиції з вашої таблиці) з фільтрами за брендом і міцністю — сайт `/menu`, бот `/menu`.
- Бронювання столика: візуальна схема залу (2 зони: «Смарагдова кімната», «Тераса», 8 столиків) — сайт `/booking`, бот `/book` (покроковий діалог).
- Замовлення забивки на самовивіз: мікс до 4 смаків, вибір вугілля, дати й часу — сайт `/order`, бот `/order`.
- Захист від подвійного бронювання одного столика на той самий час.
- Нотифікація в адмін-чат Telegram про нові брони/замовлення (опційно).

## Швидкий старт (локально)

Знадобиться Node.js 20+.

```bash
npm install

# створити схему бази й наповнити її смаками/столиками з таблиці
npm run db:push
npm run db:seed

# запустити сайт (http://localhost:3000)
npm run web:dev

# в іншому терміналі — запустити бота (потрібен TELEGRAM_BOT_TOKEN, див. нижче)
npm run bot:dev
```

## Налаштування бота

1. Створіть бота через [@BotFather](https://t.me/BotFather) → `/newbot`, скопіюйте токен.
2. Скопіюйте `bot/.env.example` у `bot/.env` і впишіть токен:
   ```
   TELEGRAM_BOT_TOKEN=ваш_токен
   TELEGRAM_ADMIN_CHAT_ID=   # опційно — id чату/групи для сповіщень про нові брони
   WEBAPP_URL=               # заповнити після деплою сайту (див. нижче)
   DATABASE_FILE=/абсолютний/шлях/до/data/tyaga.db
   ```
3. `npm run bot:dev` (або `npm run start --workspace=bot` для продакшн-режиму).

Без `WEBAPP_URL` бот працює повністю в текстовому режимі (кнопки Telegram) — це вже готовий
робочий сценарій. Коли сайт буде задеплоєний на власному домені з HTTPS, вкажіть цей домен у
`WEBAPP_URL` — тоді кнопки «Забронювати столик» і «Забивка на самовивіз» відкриватимуть саме
сторінки сайту прямо всередині Telegram (Mini App) замість текстового діалогу.

## Деплой

Це робочий продукт, але сама хмарна сесія Claude не тримає нічого онлайн після завершення —
вам потрібно розгорнути це на своєму хостингу. **Покроковий гайд для Railway (найпростіший
варіант, без власного сервера) — у [`DEPLOY.md`](./DEPLOY.md).**

Коротко: `npm run start` у корені запускає сайт і бота **одночасно в одному процесі**
(`concurrently`), щоб вони гарантовано ділили один файл `data/tyaga.db` на одному диску —
саме так налаштовано деплой на Railway з одним постійним Volume.

⚠️ SQLite-файл повинен лежати на постійному диску — на serverless-платформах на кшталт Vercel
файлова система ефемерна, тому такий варіант тут не підходить (ані для сайту, ані тим більше
для бота, який має працювати 24/7). Якщо згодом захочете перейти на Postgres — Drizzle
підтримує це заміною драйвера в `packages/db/src/index.ts` та `schema.ts`, без переписування
логіки застосунку.

## Наповнення даними

- Смаки/бренди/міцність беруться з `packages/db/src/flavors.json` (згенеровано з вашої
  фінальної таблиці Excel). Щоб оновити смаки — відредагуйте цей файл (або перегенеруйте його
  з нової версії таблиці) і запустіть `npm run db:seed` ще раз (безпечно перезапускати,
  дублікатів не буде).
- Столики й зони налаштовані у `packages/db/src/seed.ts` (масив `tableDefs`) — orientировочно,
  за вашими фото інтер'єру (3 столики в смарагдовій кімнаті, 5 на терасі). Поправте номери,
  місткість чи позицію (`x`/`y` у відсотках від 0 до 100) і запустіть `npm run db:seed`.
- Кольори бренду — у `web/src/app/globals.css` (змінні `--emerald`, `--brass`, `--terracotta`,
  `--background` тощо) — легко замінити на офіційну палітру, якщо з'явиться брендбук.
- Реальні фото інтер'єру вже підключені як фон на головній сторінці й у бронюванні
  (`web/public/interior/`).
- Адреса закладу та графік роботи — заглушки (`TODO` у `web/src/lib/constants.ts` і
  `web/src/app/contacts/page.tsx`) — впишіть реальні дані.
